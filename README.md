# RikkaHub X

> **RikkaHub X** 是 [RikkaHub](https://github.com/rikkahub/rikkahub)(上游官方项目)的个人定制 fork,仅自用,请优先支持上游。

## X 版在官方基础上增加 / 调整

- 🔀 **会话级独立模型切换**:每个会话可单独指定模型,互不影响;解析优先级 `会话模型 → 助手模型 → 全局默认`,历史会话未设置则自动回退,重启不丢
- 🏷️ **消息来源显示**:每条 AI 回复末尾灰字标注实际生成的「路由 · 模型」(如 `my-claude-relay · claude-sonnet-4-5`);会话内切换模型后,新回复上方会出现"以下回复由 xx 生成"的分隔线——每条回复出自哪个路由/模型一目了然,便于核对输出来源与成本归因
- 🖼️ **图片识别只针对新图**:历史消息含图后继续纯文字对话,不再强制进入图片识别流程,也不会对历史图片反复调 OCR——避免打断对话、保住上下文前缀缓存
- 🔊 **语音输入设置**:两个开关分别控制语音输入时的**提示音**(默认关 = 静音)与**振动**(默认开 = 强振,关 = 原版轻振);集中收纳在「设置 → 偏好设置 → **X Custom**」页
- 📝 **会话草稿自动保存**:输入内容按会话持久化,切换窗口 / 切走再回来 / 杀进程重进都不丢;发送或手动清空后自动清除,不会"幽灵回填"
- 🔘 **上下文用量圆环**(X Custom 开关,默认关):输入区实时显示当前会话上下文用量,分档变色预警,点击可快速压缩
- 🧠 **模型上下文容量表**:表**不内置在 APK 里**(App 只带解释器),联网获取后缓存本地,每 **6 小时**自动更新一次(间隔写在数据文件内,调整它无需发版);取数只走 **GitHub 官方两路**(优先不经 CDN 缓存的一路,新数据推完即可取到);数据声明的**版本时刻**若异常(超前当前时间 24 小时以上、缺失或无法解析)则**整表拒用**、保留上一份可用表 —— 否则一个写错年份的版本会永久钉死更新;手动更新未取到新数据时会自动重试 **3 次**(点击后 5 / 10 / 15 分钟),之后回到定时更新
- 🗜️ **压缩会话增强**:压缩完成升级为系统通知提醒(压缩前自动请求通知权限,避免压缩结果静默丢失)
- 🏷️ **MCP 显示名解耦**:每个 MCP 服务器可设独立显示名(支持中文),与内部 ASCII 标识分离,配置/工具链路互不影响
- 📤 **工作区归档导出/导入**:工作区可整体导出为归档包,亦可从归档包导入还原,便于迁移
- 📥 **官方备份导入**:可直接导入官方 RikkaHub 的含数据库备份(自动补齐 X 的 schema 差异列)
- 📦 **与官方同机共存**:正式版包名 `me.rerere.rikkahub.x`、应用名 `RikkaHub X`,与官方数据隔离、互不干扰
- 🧪 **测试包也能共存**:nightly 用 `me.rerere.rikkahub.x.nightly`(应用名带 ` Nightly` 后缀),
  与正式版是**两个应用**,可以同时装 —— 装 nightly 试新功能不必先卸载正式版。
  且 nightly 与正式版**同一把签名密钥**,故连续两次 nightly 之间可直接覆盖升级(不必每次重装)
- 🛡️ **eval_javascript 工具加固**(内存 / 日志 / 错误护栏)
- ⚙️ **CI 无 secrets 降级构建**(fork 无 secrets 也能产出 Release APK)
- 🔌 **不接入官方 Firebase 项目**(占位配置,待自有账号)
